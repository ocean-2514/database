# 03 数据库设计素材

> 对应《系统设计报告》第二/三/四章。概念结构 E-R 图见 `docs/er/诗歌系统ER图.drawio`（3 页：初步 E-R 图、基本 E-R 图·诗歌域、基本 E-R 图·用户域）。

## 一、概念结构设计（要点摘录）

- **8 个实体**：诗人、诗歌、诗集、流派、用户、评分记录、评论、收藏记录（评分记录/收藏记录为联系实体，user_id、poem_id 通过联系表达）。
- **9 个联系**：创作（诗人-诗歌 1:n）、属于（诗歌-流派 m:n）、收录（诗集-诗歌 m:n）、用户/诗歌 与 评分记录/评论/收藏记录 各为 1:n。
- 详细属性清单与 Mermaid 版关系图见 `docs/er/ER图说明.md` §二~§四。

## 二、逻辑结构设计（关系模式与 3NF）

### 2.1 关系模式（8 实体 + 2 个 m:n 联系 = 10 个模式）

1. 诗人(<u>poet_id</u>, 姓名, 笔名, 性别, 生年, 卒年, 国籍, 简介)
2. 诗歌(<u>poem_id</u>, 标题, 正文, 创作年份, 体裁, 字数, 赏析, *poet_id*)
3. 诗集(<u>collection_id</u>, 诗集名称, 出版年份, 出版社, ISBN, 简介)
4. 流派(<u>genre_id</u>, 流派名称, 描述)
5. 用户(<u>user_id</u>, 用户名, 密码哈希, 邮箱, 角色, 注册时间, 账户状态)
6. 评分记录(<u>rating_id</u>, *user_id*, *poem_id*, 评分, 评分时间)
7. 评论(<u>comment_id</u>, *user_id*, *poem_id*, 评论内容, 评论时间, 点赞数)
8. 收藏记录(<u>favorite_id</u>, *user_id*, *poem_id*, 收藏时间, 收藏类型)
9. 诗歌-流派(<u>*poem_id*, *genre_id*</u>)
10. 诗集-诗歌(<u>*collection_id*, *poem_id*</u>, 篇目序号)

（带下划线为主键，斜体为外键）

### 2.2 范式判定与规范化

- **1NF**：所有属性原子。反例论证：若将诗歌的流派以逗号串存入诗歌表则违反 1NF，故拆出"诗歌-流派"关联表。
- **2NF**：仅有复合主键的两个模式（诗歌-流派、诗集-诗歌）中，"篇目序号"完全函数依赖于 (collection_id, poem_id) 整体，不存在部分依赖。
- **3NF**：各模式非主属性间不存在传递依赖——诗歌表只存 poet_id 不存诗人姓名，评论表只存 user_id 不存用户名；诗歌表的"字数"函数依赖于"正文"（可由正文计算），对主键构成传递依赖，属**有意的反范式冗余**：由触发器 `trg_poem_word_count_bi/bu` 在写入时自动维护一致性，换取列表页免于实时计算。若追求严格 3NF 可删除该列改为查询时 `CHAR_LENGTH` 计算——两种方案均已在报告中论证，实现采用前者。
- **附加完整性**：评分记录与收藏记录上 `UNIQUE(user_id, poem_id)` 保证同一用户对同一首诗仅一条记录；评分 `CHECK (score BETWEEN 1 AND 5)`。

## 三、物理结构设计

### 3.1 存取方法

- **聚簇索引**：InnoDB 各表以自增 BIGINT 主键聚簇存储，主键访问 O(log n) 且自增写入避免页分裂。
- **二级索引（B+ 树）**：见 3.2 索引清单。
- **全文索引**：`poem(title, content)` 采用 **FULLTEXT + ngram 解析器**——ngram 将中文按 2 字元滑窗切词，使 `MATCH...AGAINST` 支持中文；与 `LIKE '%kw%'` 相比可利用索引且自带相关度排序。

### 3.2 索引清单

| 表 | 索引 | 类型 | 支撑的功能/语句 |
| --- | --- | --- | --- |
| poem | PRIMARY(poem_id) | 聚簇 | 详情/所有按 ID 访问 |
| poem | idx_poem_title(title) | B+树 | 标题模糊检索前缀匹配 |
| poem | idx_poem_year(create_year) | B+树 | 年代范围筛选 |
| poem | idx_poem_form(form) | B+树 | 体裁筛选 |
| poem | ft_poem_title_content(title,content) | FULLTEXT ngram | 正文/标题全文检索 |
| poem | fk 索引(poet_id) | InnoDB 自动 | 诗人联接、级联 |
| rating | uk_rating_user_poem(user_id,poem_id) | 唯一 | 防重复评分；ON DUPLICATE KEY 定位 |
| rating | idx_rating_poem_score(poem_id,score) | B+树 | 平均分聚合（覆盖索引） |
| comment | idx_comment_poem_time(poem_id,comment_time) | B+树 | 评论分页+时间倒序（免 filesort） |
| favorite | uk_favorite_user_poem(user_id,poem_id) | 唯一 | 防重复收藏 |
| user | uk_user_username / uk_user_email | 唯一 | 登录查询、注册查重 |
| poet | idx_poet_name_year(name,birth_year) | B+树 | 按诗人姓名检索 |
| genre | uk_genre_name(name) | 唯一 | 流派防重 |
| collection | uk_collection_isbn(isbn) | 唯一 | ISBN 防重 |
| poem_genre / collection_poem | 复合主键 | 聚簇 | m:n 关系防重 + 双向查询 |

### 3.3 完整性约束清单

| 约束 | 内容 | 拦截场景（实测） |
| --- | --- | --- |
| 主键 | 10 表各自自增主键 | - |
| 外键 | fk_poem_poet(RESTRICT)、fk_rating/comment/favorite_*（CASCADE）、fk_pg_*、fk_cp_*（CASCADE） | 下架诗歌级联清理互动数据；诗集删除仅级联收录关系 |
| CHECK | chk_rating_score：score BETWEEN 1 AND 5 | 越界评分入库被拒 |
| UNIQUE | uk_user_username、uk_user_email、uk_genre_name、uk_collection_isbn、uk_rating_user_poem、uk_favorite_user_poem | 重名用户/流派、重复评分收藏 |
| ENUM | gender、role、status | 非法枚举值入库被拒 |
| 触发器 | 见实现报告素材 `04-SQL与运行结果.md` | 字数自动维护、删除保护、评分时间合法性 |

### 3.4 引擎与字符集

- 引擎统一 **InnoDB**：支持事务、行锁、外键（MyISAM 不支持，故不选）。
- 字符集 **utf8mb4 + utf8mb4_unicode_ci**：完整中文与生僻字；连接层统一 `SET NAMES utf8mb4`（脚本内已内建，规避 GBK 客户端乱码问题）。

## 四、关系模式优化（报告第三章第 3 节）

- **合并外模式视图**：`v_poem_brief`（列表+统计）、`v_poem_detail`（详情聚合）、`v_collection_catalog`（诗集目录）将多表连接与聚合封装为外模式，应用层直接查询，逻辑模式变更时前端零改动。
- **计数类统计：查询时计算 vs 冗余存储**：平均分/评论数/收藏数在查询时计算（变化频繁、联动维护成本高，`idx_rating_poem_score` 支撑聚合）；字数冗余存储+触发器维护（一次写多次读且要求与正文强一致）。两种策略对比论证。
- **并发写入优化**：评分采用 `ON DUPLICATE KEY UPDATE` 覆盖写，将"查-判-写"三步合并为数据库原子操作，消除竞态。
