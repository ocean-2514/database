# 03 数据库设计素材

> 对应课程报告中的概念、逻辑和物理结构设计。详细依据见 `../子任务1-3_需求与数据库设计.md`，本文件不另设字段或约束。

## 1. 概念结构

数据库含 8 个核心实体：诗人、诗集、诗歌、流派、用户、评分记录、评论、收藏记录；另设 `poem_genre` 和 `collection_poem` 两个多对多联系表。诗人—诗歌为 1:N；诗歌—流派和诗集—诗歌为 M:N；评分、评论和收藏各关联一个用户及一首诗。

E-R 图见 `../er/诗歌系统ER图.drawio`。诗歌字数和互动统计均为查询时派生值，不作为基础表冗余字段保存。

## 2. 逻辑结构与 3NF

10 个关系模式如下：

1. `poet(poet_id, name, pen_name, gender, birth_year, death_year, nationality, dynasty, biography, created_at, updated_at)`
2. `poetry_collection(collection_id, collection_name, publication_year, publisher, isbn, description)`
3. `poem(poem_id, title, content, creation_year, poem_form, appreciation, poet_id, publication_status, created_at, updated_at)`
4. `genre(genre_id, genre_name, description)`
5. `app_user(user_id, username, password_hash, email, role, account_status, registered_at)`
6. `poem_rating(rating_id, user_id, poem_id, score, rated_at, updated_at)`
7. `poem_comment(comment_id, user_id, poem_id, content, like_count, created_at, updated_at)`
8. `poem_favorite(favorite_id, user_id, poem_id, favorited_at, favorite_type)`
9. `poem_genre(poem_id, genre_id)`
10. `collection_poem(collection_id, poem_id, sequence_no)`

各列保持原子值，M:N 关系单独拆表。实体表的非键属性依赖候选键；联系表以复合键唯一标识关系，诗集内篇目顺序由诗集和诗歌组合决定。名称、用户名、邮箱、ISBN、评分/收藏用户—诗歌组合以及诗集内序号按业务规则添加唯一约束。派生字数不保存，因此不引入其与正文之间的冗余依赖；关系模式按设计说明中的函数依赖分析满足 3NF。

## 3. 物理设计摘要

- DBMS：MySQL 8.0.16+；引擎 InnoDB；字符集/排序规则 `utf8mb4` / `utf8mb4_0900_ai_ci`。
- 主键：自增 `BIGINT UNSIGNED`；历史年份用有符号 `SMALLINT`，未知值用 `NULL`。
- 文本：诗歌正文用 `MEDIUMTEXT`；简介、赏析和评论用 `TEXT`。
- 主要索引：诗人姓名与朝代索引；诗集名称和 ISBN 索引；诗歌作者/年份索引；流派名唯一索引；用户账号/邮箱唯一索引；联系表反向索引；评分、评论、收藏的用户或诗歌访问索引。
- 中文检索：诗歌标题和正文各建一个 ngram FULLTEXT 索引。长词可用 `MATCH ... AGAINST`；短词/前缀由应用以 `LIKE` 处理。
- 删除与发布：诗歌软下架；用户停用；互动记录使用 RESTRICT 外键保留历史。仅纯多对多关联随其引用实体删除。
- `utf8mb4_0900_ai_ci` 下用户名和邮箱以不区分大小写方式唯一比较；ISBN 写入前规范化（去除连字符、末位 `x` 转大写 `X`）。
- 约束：评分范围 1—5，评论内容长度 1—2000 字符；诗人出生年不晚于卒年；诗集出版年份及收录顺序有检查约束。

实际 SQL 定义分别见 `../../sql/02_create_tables.sql` 和 `../../sql/03_indexes.sql`。
