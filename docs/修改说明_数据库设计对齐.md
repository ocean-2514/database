# 数据库设计对齐修改说明

本文记录本次将 `db/` 其他文件统一到 `子任务1-3_需求与数据库设计.md` 后的主要变化。比较基准为仓库原有文件版本；设计基准文件和课程指导手册未修改。

## 一、整体变化

旧文件中 SQL、E-R 图和报告素材采用了早期字段与规则，彼此也有不一致。本次统一到 MySQL 8.0.16+、InnoDB、`utf8mb4_0900_ai_ci`，共 10 个关系模式（8 个核心实体表和 2 个多对多联系表）。

| 设计点 | 原版本 | 当前版本 |
|---|---|---|
| 表命名 | `collection`、`user`、`rating`、`comment`、`favorite` | `poetry_collection`、`app_user`、`poem_rating`、`poem_comment`、`poem_favorite` |
| 诗歌字段 | `create_year`、`form`，存储 `word_count` | `creation_year`、`poem_form`；`word_count` 由 `CHAR_LENGTH(content)` 派生，不落表 |
| 诗人信息 | 缺少朝代/时期与创建、更新时间 | 增加 `dynasty`、`created_at`、`updated_at`；年份为有符号 `SMALLINT` |
| 诗歌状态 | 没有发布状态字段 | 增加 `publication_status`，以 `published/withdrawn` 发布或下架 |
| 用户字段 | `reader/admin`、`active/banned`，邮箱可空 | `user/admin`、`active/disabled`，邮箱必填；账户状态用于停用 |
| 互动数据 | 评分、评论、收藏可随用户/诗歌级联删除 | 互动外键使用 `RESTRICT`，保留互动记录；仅多对多联系行级联 |
| 中文检索索引 | 标题和正文共用全文索引定义 | 标题和正文分别建立 ngram FULLTEXT 索引 |
| 统计数据 | 部分统计依赖已存字数 | 字数、平均分、评分/评论/收藏数量在视图或查询时计算 |

用户名、邮箱按数据库排序规则进行不区分大小写的唯一比较。ISBN 写入前应移除连字符并规范末位 `X`。

## 二、SQL 文件变化

### `sql/01_create_database.sql`

移除 `DROP DATABASE`，改用 `CREATE DATABASE IF NOT EXISTS`，避免初始化时删除已有数据库和数据。数据库默认排序规则统一为 `utf8mb4_0900_ai_ci`。

### `sql/01_poetry_schema_mysql.sql`

改为 `01_create_database.sql`、`02_create_tables.sql`、`03_indexes.sql` 的单文件等价版本。既可分步初始化，也可执行该合并文件；两种方式不要重复执行。

### `sql/02_create_tables.sql`

重写 10 张表的 DDL，具体变化包括：

- 统一表名和字段名，并补全设计说明中的 `dynasty`、时间戳、账户状态及诗歌发布状态。
- 去掉 `poem.word_count` 持久化列。
- 将生年、卒年和创作年份改为有符号年份，以允许表示公元前；未知年份仍用 `NULL`。
- 添加或统一检查约束：诗人生卒年顺序、诗集出版年份、非空标题/正文、正数收录顺序、评分 1—5、评论长度 1—2000。
- 保留/落实业务唯一约束：流派名、用户名、邮箱、ISBN、用户—诗歌评分/收藏组合，以及诗集内篇目序号。
- 评分、评论、收藏对用户和诗歌的外键改为限制删除；只有纯多对多联系表使用级联删除。
- 普通索引和唯一索引在建表时定义，命名与设计说明保持一致。

### `sql/03_indexes.sql`

普通索引已移至建表脚本。本文件只为 `poem.title` 和 `poem.content` 分别创建 ngram FULLTEXT 索引 `ft_poem_title`、`ft_poem_content`，便于分别执行标题和正文全文检索。

### `sql/04_views.sql`

重写三个视图：

- `v_poem_brief`：只显示已发布诗歌，派生字数，并汇总评分、评论和收藏统计。
- `v_poem_detail`：使用新字段名，汇总作者、流派、诗集和互动统计；评论正文仍由独立查询分页读取。
- `v_collection_catalog`：使用 `poetry_collection` 新字段名，统计诗集内已发布作品数。

### `sql/05_triggers.sql`

删除维护 `word_count` 的插入/更新触发器，因为字数现在是派生值。保留并调整诗人删除保护、管理员账户物理删除保护；新增评分插入和更新时的未来时间校验，共 4 个触发器。

### `sql/06_procedures.sql`

更新 4 个存储过程以匹配新模式：

- `sp_search_poems`：加入朝代/时期和诗集筛选，使用有符号年份，限制结果为已发布诗歌，并校正分页边界。
- `sp_fulltext_search_poems`：分别检索标题与正文全文索引；短词/前缀检索由调用方按设计使用 LIKE 兜底。
- `sp_register_user`：用户名或邮箱重复时拒绝注册，新用户使用默认普通用户角色。
- `sp_add_collection_with_poems`：改用新诗集字段与 `sequence_no`，在事务中创建诗集并按输入顺序收录；异常时回滚。

### `sql/07_seed_data.sql` 与 `sql/08_expand_data.sql`

种子数据和扩充数据已改用新表名、字段名和枚举值；诗人数据补充 `dynasty`，评分/评论/收藏插入改用新互动表。脚本不再写入 `word_count`，扩充脚本的检查查询也改为读取视图派生结果。演示 ISBN 使用无连字符格式。
